# coverage-information differential corpus

Synthetic CRD 2.2.1 `ext-coverage-information` cases. The official HL7 FHIR
validator judges them, and `CoverageInformationDifferentialTest` checks that
`CoverageInformationValidator` agrees.

- `cases/*.json`: one ServiceRequest per case, carrying one extension. The
  `valid-*` cases are conformant bases. The other cases mutate a base:
  - `missing-*`: a required sub-extension removed;
  - `twice-*`: cardinality broken;
  - `code-*`: a code outside its value set;
  - `date-*`: a malformed date;
  - `type-*`: a wrong value type;
  - `unknown-*`: an unknown sub-extension;
  - `detail-*`: a broken `detail` part (missing, repeated, wrong type or
    code);
  - `q1`–`q9`: an invariant broken.
- `official-verdicts.json`: generated by `fhir-validator/run.sh`. Do not edit
  it by hand. CI's `fhir-validator` job regenerates it and fails if it
  changes.
- `known-differences.json`: cases where we disagree with the official
  validator. Each one is either deliberate (DECISIONS.md, "Differential
  testing against the official validator") or an open bug issue.

To add a case, add its file and run `fhir-validator/run.sh`. Commit the case
and the regenerated verdicts together. If the new case disagrees with the
official validator, fix the validator or record why. Do not change the case
to make it agree.
